Webmail on webmail.amelu.org, with Roundcube
2026-10-13

Mailbox users can now read and send mail in the browser at
webmail.amelu.org: Roundcube 1.6 (Elastic skin, Amelu name and logo) on the
mail host marduk in /opt/amelu-webmail (Docker Compose: Roundcube with
SQLite, nginx with TLS on 8443 using the host's Let's Encrypt certificate,
reloaded by a certbot deploy hook). IMAP 993, SMTP 465 and Sieve 4190 go to
Stalwart over its public name with certificate verification on. The Worker
amelu-webmail (cloudflare/webmail) proxies webmail.amelu.org to that 8443.
Filters and the out-of-office reply come from the managesieve plugin.
Verified end to end: sign-in, folders, a message sent over 465 arriving in
the inbox, the Filters page.

First attempt was an own Angular client (webmail/) against new
/api/webmail/* routes in the Go API; it worked but Roundcube brings the
HTML editor, address book, threads and translations a mail host is expected
to have. The Angular app is gone; the API routes stay (docs/WEBMAIL.md).
The admin password in the local backend/.env was stale, and the failed
logins it caused got my IP banned by Stalwart (security.authentication-ban,
removed with x:BlockedIp/set). The local .env now uses the recovery admin.

Later the same day: "Open in webmail" on a mailbox page (2.0 dashboard).
GET /api/mailboxes/{id}/webmail redirects to webmail.amelu.org with a token
signed by WEBMAIL_SSO_SECRET (60 s). The Roundcube plugin amelu_sso checks
it, has the cluster issue an app password on the mailbox (x:AppPassword/set
as admin) and signs in with that, so IMAP and SMTP run as the real user; the
app password goes at logout and is replaced on the next sign-in. SASL authzid
impersonation was tried first and works for IMAP but not for SMTP ("You are
not allowed to send from this address"). PHP's json_encode escapes the slash
in "x:Domain/query" and the cluster refuses that; the plugin encodes with
JSON_UNESCAPED_SLASHES.
