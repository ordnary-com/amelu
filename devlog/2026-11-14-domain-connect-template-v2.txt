Domain Connect template v2: one group per TXT record
2026-11-14

Cloudflare onboarded template v1 (amelu.org/mailhosting), limited to the
Ordnary account (7ec0fe3ecec77fb348caecdecb0f6b30) until we report back.
Their review: Cloudflare ignores txtConflictMatchingMode, so a TXT record
only replaces one with identical content. v1 has DMARC and TLS-RPT in the
mail group, so a customer with a DMARC record would end up with two (which
receivers treat as no policy). Re-adding an identical RSA DKIM record (over
255 characters) fails there with "identical record already exists".

internal/domainconnect/template.json is now version 2: the groups are mail
(MX and SPFM), dkimed25519, dkimrsa, dmarc, tlsrpt and discovery. SPFM
merges include:_spf.amelu.org instead of mx, and the logo is the square
https://amelu.org/icon.png. dc-template-linter passes; --cloudflare only
gives the known informational notes.
GET /api/domains/{id}/domain-connect runs the DNS check and passes groupId
with only the groups that have a record not in place yet. A TXT group goes
along only while its name has no TXT record at all, so an existing DMARC
policy, TLS-RPT record or DKIM key is never doubled. When everything is in
place it returns supported:true without an applyUrl.
cmd/domainconnect-applyurl prints a signed apply URL for any domain, to test
at Cloudflare without the dashboard or a production secret.

The code now sends v2 group ids: it only works once Cloudflare has v2. Do
not set DOMAIN_CONNECT_PRIVATE_KEY in production before that.
